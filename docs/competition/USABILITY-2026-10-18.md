# 可用性走查（2026-10-18）

**性质**：自动化专家走查，不是真人可用性测试。用脚本模拟第一次来访的用户完成常见任务，记录步数、等待时间、首屏能看到什么、键盘能否操作、触控目标大小，并用 axe-core 4.14 做无障碍检查；再按 Nielsen 十条启发式原则逐屏评估。真人测试请按 [TRIAL_GUIDE.md](TRIAL_GUIDE.md) 的任务和 SUS 问卷做。

- 对象：生产构建（HEAD `474c66a`），本机 `http://localhost:3210`；桌面 1440×900，手机 390×844（触屏模拟）。
- 脚本：[`eval/usability/walkthrough.py`](../../eval/usability/walkthrough.py)；结果：[`eval/results/usability-2026-10-18/walkthrough.json`](../../eval/results/usability-2026-10-18/walkthrough.json)（截图只留在本地）。
- 本机测速，没有真实网络延迟；外部数据库和模型的耗时会随网络变化。

## 启发式评估

严重度：4 阻碍使用，3 严重，2 一般，1 轻微。

| 严重度 | 问题 | 原则 | 建议 |
|---:|---|---|---|
| 4 | 访客没法直接用：只能本机运行，没有公网地址 | 访问门槛 | 部署公网演示（官方加分项），服务端持有密钥并保留现有限额 |
| 3 | 报告只能下载 .md，多数老师不知道怎么打开、打印 | 贴近用户习惯 | 增加打印版 / PDF / Word 导出 |
| 3 | 正文段落被当成参考文献核查，给出“去知网核查”的误导结论 | 防错 | 输入不像参考文献时（没有年份、作者、题名特征）先提示 |
| 3 | 首屏看不到主操作，“载入示例”是小号浅灰链接 | 可见性 | 把“开始体检”“试一试示例”放进首屏；手机用底部固定按钮 |
| 2 | 对比度不足、输入框无焦点框、触控目标太小 | 无障碍 | 加深 `ink-faint`，给输入框加焦点样式，加大按钮点击区域 |
| 2 | 首次加载 2.0 MB（主要是字体） | 效率 | 字体再按页面实际用字裁剪，或首屏先用系统字体 |
| 2 | 老师批改多份作业要一份份粘贴，没有历史、没有分享链接 | 灵活高效 | 多份清单批量体检、按学生汇总；结果导出或只读分享 |
| 2 | 复制修正版清单前看不到内容 | 可见性 | 复制前展示改动对照（原文 → 修正） |
| 1 | “匹配参考值 98%”“健康度”的含义要看说明才懂 | 贴近用户习惯 | 改成“多像同一篇”这类说法，或悬停解释 |
| 1 | 图书条目点“AI 继续查”要等十几秒，通常查不到 | 状态可见 | 按钮旁提示“图书、学位论文通常查不到” |
| 1 | 空输入时按钮变灰但不说明；超长输入点了才提示 | 防错 | 输入框下方实时显示条数和字数上限 |
| 1 | 印章会压住引文最后几个字 | 美观 | 印章区域预留右边距 |
| 1 | 报告文件名日期按 UTC | 一致性 | 用本地日期 |

## 做得好的地方

- 结论分层清楚：印章、颜色、筛选标签和“发现 N 条需要处理”一眼能看到重点。
- 过程透明：每条都能展开核查过程，“AI 继续查”逐步显示理由和结果。
- 手机端没有横向溢出，点开始后自动滚到结果。
- 除对比度外，axe-core 没有查出标签、ARIA、地标等问题。

## 怎么让更多人用得上

**谁会用、在什么时候用**

| 用户 | 场景 | 现在缺什么 |
|---|---|---|
| 学生 | 交稿前自查参考文献，顺手改成规范格式 | 公网地址；从 Word、Zotero、知网导出格式导入；导出 GB/T 7714 / BibTeX |
| 导师、任课老师 | 批改论文时抽查，指导学生改 | 能打印的报告（PDF / Word）；多份清单一次查完、按学生汇总 |
| 学报编辑部 | 收稿后初筛引用 | 批量与接口；中文期刊覆盖；处理记录可追溯 |
| 图书馆、写作中心 | 作为校内服务开放 | 校内部署、统一认证、用量统计、隐私说明 |

**按投入排序**

1. 先上公网演示（官方加分项，也是访客能用的前提）：国内可访问的服务器，服务端持有密钥，沿用现有每 IP 限额，再加每日总额度。
2. 首屏改造：首屏放“试一试示例”和“开始体检”；手机底部固定主按钮；输入框下方实时显示条数和字数上限，并提示“这段不像参考文献”。
3. 报告导出成打印版 / PDF，修正版清单先给改动对照再复制。
4. 无障碍小修：加深浅灰文字、输入框焦点框、加大“展开详情”等按钮的点击区域。
5. 导入导出对接常用工具：RIS / BibTeX（Zotero、EndNote、NoteExpress、知网都能导出），修正结果导回 BibTeX。
6. 面向老师：多份清单批量体检、按学生汇总；只读分享链接（不存原文或限期删除）。
7. 长期：Word / WPS 插件、浏览器插件；校内部署版本和开放接口（现有 MCP 可以改成远程 HTTP）。

## 真人测试怎么补

自动化走查只能发现“能不能做完、哪里卡住”，测不出“用户懂不懂、愿不愿意用”。请按 [TRIAL_GUIDE.md](TRIAL_GUIDE.md) 找 5 位左右老师或学生，每人做同样的任务，记录完成情况、用时和卡住的地方，最后填 SUS 问卷（System Usability Scale，Brooke 1996，10 题、0–100 分）。

## 10-20 界面改版

用户觉得界面“别扭”。对照改版前的走查截图，问题集中在三处：

1. 宽屏左右两栏：左边约 400 px 宽的“送检单”里，一条英文引文要折成三四行；结果出来前，右栏是“壹贰叁肆”四段说明，首屏大半是要读的文字。手机上页面长 2880 px，首屏看不到“开始体检”。
2. 公文感重：全页默认宋体，标题和按钮再加粗，按钮文字拉开字距，输入框画成横格纸，和“打开就用的工具”不搭。
3. 结果多了以后，要筛选得滚回报告顶部；展开详情时整张卡片一下子撑开。

改版保留印章和朱红（它们本身就是结论），其余按工具来做：

| 改动 | 做法 |
|---|---|
| 版面 | 单栏，输入在上、结果在下。输入框随内容增高（最高 20 rem），下面一行工具条：载入示例、导入文件、截图识别、识别到 N 条、AI 辅助解析开关、开始体检 |
| 字体 | 正文和控件改用系统黑体（苹方、微软雅黑等），宋体只留给标题、引文和大数字 |
| 说明文字 | “会查什么”压成一行要点；结论印章做成一行图例；隐私说明收成一行，点开看全文。Ctrl / ⌘ + Enter 的提示移到新手引导第 4 步（只在宽屏显示），引导文案同步改了 |
| 页眉 | 宽屏吸顶，滚动后变毛玻璃；两个任务改成分段切换，选中项下有一块滑动的高亮底 |
| 结果 | 顶部大数字直接说结论（有问题时“N 条需要处理”，否则“N 条全部核实”）；筛选新增“需要处理”（查无此文、已撤稿、关注声明、有误），筛选栏滚动时吸在页眉下，手机上横向滑动；卡片是左侧色条 + 印章 + 一句结论，“详情”平滑展开 |
| 动效 | 开场后各块依次淡入；按下按钮时从指尖晕开一圈朱砂色；数字滚动到新值；结果卡片逐条入场；都遵循系统“减少动画”设置。没有引入新的依赖库 |
