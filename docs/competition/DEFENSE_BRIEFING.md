## 1. 一分钟看懂项目

**一句话**：引用体检是一个网页工具，帮写论文的人检查参考文献是不是真的、信息有没有写错、有没有被撤稿；还能检查正文里的一句话，有没有被它引用的材料支持。

**30 秒介绍（可以背）**：

> 大模型帮人写论文时会编造参考文献。2023 年一项研究里，GPT-3.5 生成的引文 55% 是编造的，GPT-4 也有 18%。引用体检把论文末尾的参考文献逐条拿到公开学术数据库核对：DOI 有没有注册，题名、作者、年份、期刊对不对，有没有被撤稿；中文期刊论文还会联网到知网、万方、维普和期刊官网去核对。查不到的，可以让 AI 继续找。它还能检查正文里的一句话有没有被原文支持。我们的原则是：大模型只负责找和读，真假由规则根据数据库记录判定，每个结论都附原始依据。

**2 分钟介绍（主讲用）**：在 30 秒版后面接三点。

1. **两个工作区**。“参考文献体检”给每条参考文献盖一个结论印章，比如已核实、有误、查无此文、已撤稿、待人工，展开能看到字段比对、规范写法和每一步查了哪里。“正文论断核查”读取论断所引论文的开放全文，找出原文句子，判断支持、部分支持、矛盾还是证据不足。
2. **六项 AI 能力**。分别是：受约束的字段解析、AI 检索 Agent、中文期刊联网核查、截图识别参考文献、读取开放全文的论断 RAG、开放给其他 AI 用的 MCP Server。导入论文时还会检查藏给 AI 的隐藏提示词。
3. **和直接问 AI 比**。在 130 条答案已知的引文上，不联网的 DeepSeek 把 23%–33% 的编造引文说成真实，本系统是 0；本系统说“已核实”的全部正确，改正写法全部来自数据库记录，重跑结论一致。

**入口**：

- 在线试用（魔搭创空间，不用登录）：<https://www.modelscope.cn/studios/kgkvybu111111/cite-checkup?mode=full>
- 代码仓库（公开）：<https://github.com/newhack-cpu/cite-checkup>

## 2. 要解决的问题

**AI 写作带来的引用问题是真实存在的**：

- Walters 与 Wilder（2023）让 ChatGPT 写文献综述，在他们的样本中，GPT-3.5 生成的引文有 55% 是编造的，GPT-4 是 18%；真实存在的引文里也常有书目错误。出处：*Scientific Reports*, 13, 14045，<https://doi.org/10.1038/s41598-023-41032-5>。这个比例只代表那项研究的样本，不代表现在所有模型。
- 2025 年 7 月，日经亚洲报道 17 篇 arXiv 预印本用白字、极小字号藏了“只给正面评价”之类写给 AI 审稿的指令；Lin 的评论文章统计到 18 篇（arXiv:2507.06185）。

**目标用户**：用 AI 辅助写作、需要自查参考文献的学生；指导老师和审稿人；高校图书馆、写作中心（后续试点方向）。

**我们把“引用可不可信”拆成两个问题**：

| 问题 | 怎么回答 | 依据 |
|---|---|---|
| 这篇文献存在吗？信息写对了吗？ | 拿到数据库逐字段核对 | Crossref、doi.org、OpenAlex、DataCite、中国 DOI 注册机构、知网 / 万方 / 维普 / 期刊官网页面 |
| 正文这句话被它支持吗？ | 读原文、找出处句子、判断关系 | Europe PMC / arXiv 开放全文、摘要或用户提供的材料 |

文献存在不等于论断成立，所以两件事分开查、分开下结论。

## 3. 用户能做什么

### 3.1 参考文献体检

**输入有四种**：

- **粘贴**：支持 `[1]`、`1.` 编号、空行分段、续行合并，GB/T 7714、APA、IEEE 等格式；只贴 DOI 也行。
- **导入文件**：PDF、DOCX、TXT，预览后选全文或参考文献区域，确认才替换输入。
- **截图识别**：上传或直接粘贴 1–4 张截图、照片。
- **载入示例**：11 条内置示例，包括故意改错和虚构的条目。

**每条输出**：一个结论印章 + 一句话结论；展开“详情”能看到字段比对表（题名、作者、年份、期刊、DOI）、按数据库记录生成的规范写法、核查过程（每一步查了哪个库、结果、耗时）和来源链接。

**八种结论**（界面印章上的字）：

| 印章 | 含义 | 典型例子 |
|---|---|---|
| 已核实 | 文献存在，题名、作者、年份、期刊、DOI 与数据库一致 | 示例第 1 条 Walters & Wilder 2023 |
| 有误 | 确认是同一篇，但某项写错；或引用的 DOI 未注册、指向别的文献 | 示例第 4 条把期刊写成 Neural Networks（应为 Neural Computation） |
| 相近候选 | 找到相近记录，但不能确认是同一篇；不算写错，请人工核对 | 中文论文在知网找到题名一致的文章，但作者核对不了 |
| 查无此文 | 有较强证据表明文献不存在：DOI 未注册或指向别的文献且查不到同名文献，或看得出是期刊论文却在两个数据库都查不到 | 示例第 6 条 DOI 未注册 |
| 已撤稿 | 文献被撤稿或撤回 | 示例第 9 条 Wakefield 1998（2010 年撤稿） |
| 关注声明 | 期刊发了关注声明（Expression of Concern），不等于撤稿 | — |
| 待人工 | 图书、学位论文、网页等不在开放数据库覆盖范围，或中文文献联网也没核对到；**查不到不代表不存在** | 示例第 11 条周志华《机器学习》（图书） |
| 未完成 | 数据源暂时不可用、限流或超时，可以重试；不当作“不存在” | — |

**后续操作**：

- 按结论筛选，“需要处理”只看有问题的条目。
- 对“待人工 / 相近候选”点“AI 继续查”。
- 点“规范参考文献”把整份列表统一成 GB/T 7714 或 APA 第 7 版：数据库确认是同一篇的按记录重写，其余保留原文并注明原因。
- 复制修正版清单；下载核查报告（网页版可直接打印成 PDF，另有 Markdown 版）。

### 3.2 正文论断核查

- **输入**：一句论断 + 它引用的论文 DOI，或者直接粘贴证据材料。
- **输出**：
  - 四类判断之一：证据支持、部分支持、与证据矛盾、证据不足。
  - 一段解释。
  - 逐字核对过的原文引句，可以定位到原文位置。
  - 证据范围：读到的是全文还是摘要。

### 3.3 其他

- **隐藏提示词检测**：导入 PDF / DOCX / TXT 时，找出读者看不见、AI 却会读到的文字，像写给 AI 的指令会列出并从导入文字中去掉。
- **MCP Server**：把“核验参考文献”“核查论断”两个工具开放给 Claude、Cursor 等 AI 工具调用（本机 stdio）。
- **上手引导**：
  - 第一次打开有约 2 秒的落印开场动画，以及 6 步新手引导。
  - 页眉“怎么用”可以随时重看。
  - 输入框里按 Ctrl / ⌘ + Enter 直接开始。
  - 动效都遵循系统的“减少动画”设置。

## 4. 系统怎么工作

### 4.1 技术栈

- **前端与服务端**：Next.js 16（App Router）+ React 19 + TypeScript（严格模式）+ Tailwind CSS 4。网页和接口在同一个 Next.js 应用里，接口是 `src/app/api/*/route.ts`。
- **大模型**：DeepSeek（`deepseek-flash`）。用到函数调用（Function Calling）、多轮工具调用、图片输入，以及 DeepSeek 的搜索接口（这是搜索引擎，不是大模型）。
- **数据源**：Crossref、doi.org、OpenAlex、DataCite、中国 DOI 注册机构、Europe PMC、arXiv；中文期刊读知网、万方、维普和期刊官网的公开页面。
- **部署**：魔搭创空间（Docker，免费 2 核 8 GB），另有 Netlify 备用站；密钥只放在服务端环境变量。
- **规模**：源码约 1.2 万行，测试代码约 6400 行，45 个测试文件 728 项测试；Git 历史 70 多个提交（2026-10-15 首次提交）。

### 4.2 数据流

```
浏览器（React 界面：输入区、结论卡片、报告）
 │
 ├─ POST /api/check  参考文献体检，NDJSON 流式逐条返回
 │    本地解析（切条目、抽 DOI / 年份 / 题名 / 作者 / 期刊，不调外部服务）
 │    → 核验引擎 verify.ts：DOI 查询 → 整条引文检索 → 英文兜底 OpenAlex
 │      → 中文期刊联网核查（DeepSeek 搜索 + 知网 / 期刊官网页面）
 │    → 逐字段比对 match.ts → 结论 + 规范写法 + 核查过程
 │
 ├─ POST /api/agent  AI 继续查：DeepSeek 多轮决定调用哪个检索工具 → 候选交规则复核
 ├─ POST /api/claims 论断核查：开放全文 / 摘要 → 分块 → 混合检索 → 模型判断 → 引句校验
 ├─ POST /api/vision 截图识别：DeepSeek 视觉模型逐条转写 → 用户确认 → 再走 /api/check
 └─ POST /api/import 文档导入：PDF / DOCX / TXT 提取文字 + 隐藏文字检测 → 预览确认

MCP Server（stdio）→ 调用同一套核验引擎和论断核查
```

### 4.3 三条设计原则

答辩时反复强调这三条：

1. **检索与裁决分离**。大模型和搜索引擎只负责“找候选、读原文”，“是不是同一篇、真不真”由规则逐字段判定。模型不能宣布文献“不存在”，也不能指定哪一篇算数。
2. **每个判断都回到证据**。结论旁边有数据库记录、原文页链接、原文引句和每一步查询过程，用户可以自己复核。
3. **不确定就说不确定**。查不到不等于编造，判“待人工”；只找到相近的记录单列“相近候选”；数据源出错标“未完成”，不当作“不存在”。

## 5. 六项 AI 能力

每项按“做什么 → 怎么做 → 为什么这样设计 → 效果 → 代码在哪”讲。

### 5.1 受约束的字段解析（“AI 辅助解析”开关）

- **做什么**：规则解析不出题名的条目（格式乱、粘连、少标点），交给 DeepSeek 从原文里逐字摘出作者、题名、年份、刊名等字段，再交给数据库核验。
- **怎么做**：
  - 用 Function Calling 的 `verify_references` 工具。服务端固定条目边界，模型不能增删条目、不能改写原文。
  - 每个字段都要逐字核对确是原文片段。某条不合格，只这一条退回规则解析，不影响同批其他条目。
  - 摘出的刊名只校验、不用于比对；AI 摘出的题名查不到时，不作为“疑似不存在”的依据。
  - 补上的字段在比对表里标“AI 摘出”。
- **为什么**：模型擅长读乱格式，但不能让它“修好”原文里的错误证据，比如把写错的作者改对。
- **效果**：
  - 用同一批数据库应答对照开和不开：dev 和第五批结论逐条相同；test 多核实 2 条、多抓出 1 条真错误；没有新增误报。
  - 旧版整批发给模型、一条不合格就整批作废，反而多了误报，所以改成了现在的逐条做法。
  - 默认关闭，单次最多 20,000 字符。
- **代码**：`src/lib/ai/index.ts`（`prepareAIReferences`）、`src/app/api/check/route.ts`。

### 5.2 AI 检索 Agent（“AI 继续查”按钮）

- **做什么**：对“待人工 / 相近候选”的条目，由模型规划下一步查哪个库、用什么检索词，每一步实时显示在卡片上。
- **六个工具**：`search_crossref`、`search_openalex`、`search_datacite`、`search_cn_journals`（中文期刊联网搜索）、`lookup_doi`、`finish`。
- **约束**：
  - 每条最多 4 次检索、4 轮模型调用、80 秒，OpenAlex 最多 1 次。
  - 工具名、字段逐项白名单校验；DOI 只能查引文或检索结果里出现过的。
  - 规则一旦确认是同一篇就停；所有候选都要规则逐字段复核。
  - Agent 不能把文献判成“不存在”，它的检索也不计入“两个数据库都查不到”。
- **为什么收窄自主权**：查证类任务里，模型最大的风险是“替人下结论”。让它只负责找，结论仍由规则给，就不会出现“模型说有，其实没有”。
- **效果**：
  - test 集（Agent 的盲测）58 条可追查，确认 7 条（4 条已核实、3 条信息有误），没有一条变成“疑似不存在”。复核发现其中 1 条配到同一作者的新文章、1 条是报告旧版本，据此补了两条更保守的规则。
  - 中文 75 条找到三站论文页 33 条，自动确认 1 条（多数缺作者，只能给链接请人工核对）。
- **代码**：`src/lib/agent/`（`index.ts` 流程、`model.ts` 模型调用、`tools.ts` 工具与参数校验）、`src/app/api/agent/route.ts`、`src/lib/agent-stream.ts`。

### 5.3 中文期刊联网核查（标准体检自动做）与知网 DOI 核对

- **问题**：知网、万方没有开放接口，Crossref 和 OpenAlex 收录的中文期刊文章很少，以前中文期刊论文几乎全判“待人工”。
- **怎么做**：
  1. 用 DeepSeek 搜索接口（搜索引擎，不是大模型）按题名找知网、万方、维普的论文页。
  2. 读手机知网文章页内嵌的数据、期刊官网的 `citation_*` 元数据，补出作者、卷期。
  3. 必要时按刊物 ISSN、卷、起始页到 Crossref 定位。
  4. 规则逐字段判定，写明来源是知网、维普、期刊官网还是 Crossref。
- **判定规则**：
  - 判“已核实”要求题名、刊名、年份一致，作者对得上，并且卷号、期号或起始页至少一项一致。
  - 只差作者、或只差卷期页时，给“相近候选”和原文链接。
  - 题名、刊名、年份对上而作者对不上，判“信息有误”。这正是“真题名配假作者”式的拼凑编造。
- **知网 DOI 核对（10-23 加）**：
  - 知网登记的 DOI 在 doi.org 取不到元数据，现在读中国 DOI 注册机构的解析页，看这个 DOI 登记的是哪篇论文。
  - 登记的是另一篇，就按“DOI 指向别的文献”处理。
  - 登记的就是这一篇时，只说明 DOI 属于它，年份、卷期页仍请人工核对，不据此判已核实。
- **边界**：
  - 只读公开页面，不登录、不碰验证码，不绕过付费墙；WebVPN 镜像、文库这类转载站不当来源。
  - 服务器只请求公网地址，防 SSRF。
  - 每次请求最多 30 条、单条最多 25 秒；没配置 DeepSeek 密钥时整步跳过。
- **效果**：
  - 已看过的 122 条中文期刊论文，待人工从 91% 降到 32%。
  - 新抽 40 条（规则定稿后只运行一次）从 95% 降到 32.5%，已核实 15 条逐条复核全对。
  - 两者的新口径误报都是 0。
- **代码**：`src/lib/verify/cnjournal.ts`（流程）、`sources/cnweb.ts`（搜索与解析）、`sources/cnpage.ts`（读页面、SSRF 防护、中国 DOI 解析页）、`throttle.ts`（限流与缓存）。

### 5.4 截图识别参考文献（多模态）

- **做什么**：纸质论文、扫描件里的参考文献不能复制时，上传或粘贴截图 / 照片，DeepSeek 视觉模型逐条转写成文字。
- **约束**：
  - 只转写、不判断真伪，看不清写 `[?]`。
  - 用户对照原图确认后，再交给规则核验。
  - 浏览器先把图缩到 2048 像素以内、去掉 EXIF；服务端按文件头识别真实格式。
  - 模型只能调用 `submit_references`；原图只在请求内存里用，不保存。
- **效果**：合成的 16 条（英文截图 5、中文截图 5、加了倾斜模糊噪点的模拟手机照片 6）16/16 逐字一致，字符错误率 0%。这是印刷体合成样本，手写、强反光、严重透视没覆盖。
- **注意**：PDF / DOCX 导入只是文字提取，**不算**多模态。
- **代码**：`src/lib/vision/index.ts`、`src/app/api/vision/route.ts`。

### 5.5 论断 RAG（正文论断核查）

- **证据来源**：
  - DOI 依次尝试 Europe PMC 开放全文（JATS XML）、arXiv 预印本 PDF；都没有时用 Crossref / OpenAlex 摘要。
  - 也可以直接粘贴证据材料。
- **检索**：
  - 按约 1,200 字符分块。
  - 多于 6 段时用混合检索：原论断的 BM25，加模型扩展的中英文检索词的 BM25，按倒数排名融合取 20 段；再由模型按 0–3 分重排，取前 6 段。
- **判断**：
  - `judge_claim` 输出四类判断之一、解释和原文引句。
  - 服务端校验来源编号、片段编号，并确认引句能在原文中逐字找到并定位。假引句、错来源一律拒绝。
- **范围复核**：初判“矛盾”时再做一次 `check_scope`，让模型逐个列出论断里限定范围的词（文献类型、人群、年份、条件），检查引句有没有专门针对它的结果；有一项没覆盖就改判“证据不足”。
- **为什么不用向量数据库**：DeepSeek 没有向量（embedding）接口，引入另一家服务会增加依赖和数据外发；我们用“BM25 + 模型扩展检索词 + 模型重排”补语义和跨语言召回。
- **效果**：
  - 检索：24 条论断，前 6 段命中率从 75%（中文 50%）到 100%，MRR 从 0.61 到 0.98。
  - 范围复核：47 条论断两轮 280 次判定，不该判矛盾的 178 次里错判从 38 次降到 0；该判矛盾的 102 次里有 1 次被错改成证据不足。
- **代码**：`src/lib/claims/`
  - `index.ts`：总流程。
  - `sources.ts`：取摘要。
  - `fulltext.ts`：取开放全文。
  - `retrieval.ts`：分块与 BM25。
  - `assist.ts`：查询扩展、重排、范围复核。
  - `model.ts`、`judge.ts`：判断与校验。

### 5.6 MCP Server

- **做什么**：用官方 TypeScript SDK（1.31.0）以 stdio 提供两个只读工具 `verify_references`、`check_claim`，Claude、Cursor 等 AI 工具可以直接调用本项目的核验能力。
- **细节**：
  - 与网页端共用逻辑和限额。
  - 返回文字摘要和带 `outputSchema` 的结构化结果。
  - 核验时逐条发送进度通知。
- **边界**：只在本机通过 stdio 运行，没有远程 HTTP 部署和鉴权。
- **代码**：`src/lib/mcp/server.ts`、`scripts/mcp-server.mts`、`scripts/mcp-smoke.mts`（真实调用两个工具的冒烟测试）。

### 5.7 安全可控（贯穿所有功能）

- **模型输出一律当作外部输入**：工具名、字段白名单，长度、格式、出处逐项校验；任何一步失败标“未完成”，不会替换成“支持”或“已核实”。
- **隐藏提示词检测**：
  - PDF：白色填充、不可见渲染、小于 1.5 磅、页面外文字。
  - Word：隐藏格式、浅色底白字、小于 2 磅的字。
  - 所有格式：Unicode 隐形标签字符。
  - 像写给 AI 的指令一律列出并从导入文字中去掉；不判断作者意图。
- **服务器替用户访问网页时防 SSRF**：只请求公网地址，跳转逐跳检查，拦截本机、内网、云服务器元数据地址。
- **文件安全**：
  - 上限：8 MiB、100 页、160,000 字符。
  - ZIP 解压有条目数、总量、压缩比限制。
  - PDF.js worker 做完整 SHA 校验。
- **密钥与限额**：密钥只在服务端；各接口按 IP、按进程限流，超出时明确提示或回退规则核验。

**口径小词典**：

- **误报**：真实存在的文献被标成有问题。
  - 旧口径：信息有误、相近候选、疑似不存在都算误报。
  - 新口径：相近候选不算误报，因为它没有断言哪里写错，但单列条数。
- **盲测**：规则定稿后，在没见过的新数据上只运行一次。看过的数据再改规则，就只能算回归。
- **同一批复测**：看过结果、修了之后在同一批数据上再跑。效果会偏乐观，所以要说明。
- **95% 区间**：样本只有一百多条，单个百分比有很大波动，比如第五批 5.6% 的区间是 2.6%–11.6%。
- **复核**：都由开发方完成，没有第二人独立标注。这是已知局限。

## 7. 创新点与评分标准对照

### 7.1 技术创新（5 条）

1. **检索与裁决分离**：大模型和搜索引擎只找候选、给依据，是不是同一篇、真伪如何由规则逐字段判定；Agent 不能宣布“不存在”。
2. **中文证据链**：
   - 按题名找知网、万方、维普和期刊官网的原文页，读手机知网内嵌数据和官网元数据补作者、卷期。
   - 再按 ISSN、卷、页到 Crossref 定位；作者用汉字与拼音互相比对。
   - 知网登记的 DOI 到中国 DOI 注册机构核对它登记的是哪篇。
3. **论断 RAG**：开放全文优先；BM25 与模型扩展检索词融合，再由模型重排；引句逐字核对并定位；初判矛盾时做范围复核。
4. **导入与联网安全**：在 PDF 文字提取的同一遍里跟踪填充色和渲染模式，检出隐藏提示词；服务器替用户访问网页时只请求公网地址。
5. **工具开放**：同一套核验逻辑通过 MCP 开放给 Claude、Cursor 等 AI 工具。

### 7.2 应用创新（4 条）

1. **两个问题分开查**：文献是否存在、信息是否一致，和正文论断是否被原文支持，各有结论和依据。
2. **不只查错，也帮着改**：给出数据库里的规范写法，整份列表一键统一成 GB/T 7714 或 APA，只贴 DOI 也能生成。
3. **每个结论都摆出依据**：查不到不等于编造，相近候选单列，不让用户误改。
4. **面向中文论文写作**：中文界面、GB/T 7714、中文期刊联网核查，魔搭国内入口不用登录。

### 9.2 一次“参考文献体检”从点击到出结果

1. `components/checker.tsx`：用户点“开始体检”，`POST /api/check`，边收边显示（`lib/check-stream.ts` 校验流是否完整）。
2. `app/api/check/route.ts`：
   - 限流（`lib/check-limits.ts`）、读请求（`lib/check-request.ts`，最多 80 条 / 60,000 字符）。
   - `parseReferenceList` 本地解析。
   - 选了 AI 时先 `prepareAIReferences`。
   - 然后 `verifyAll` 并发 3 条核验，每完成一条就推一行 NDJSON。
3. `lib/verify/extract.ts`：切条目，抽 DOI、arXiv 编号、年份、题名、作者段、期刊、文献类型。纯本地，前端也用它实时显示“识别到 N 条”。
4. `lib/verify/verify.ts` 的 `verifyReference`（核心，读懂它最重要）：
   - 只贴 DOI → 按 DOI 补全。
   - 有 DOI → Crossref 直查；查不到问 doi.org 是否注册、内容协商取元数据；知网登记的 DOI 读中国 DOI 解析页。
   - DOI 没对上 → Crossref 整条引文检索。
   - 英文还没找到 → OpenAlex 题名检索（有额度）。
   - 中文期刊还没找到 → `cnjournal.ts` 联网核查。
   - 选出最佳候选 → `judgeSame`（同一篇：已核实 / 有误 / 撤稿）或 `judgeNotSame`（相近候选 / 查无此文 / 待人工）。
5. `lib/verify/match.ts` 的 `scoreCandidate`：拿数据库的题名、作者、期刊回到原文里找。题名按词（中文按相邻两字）算召回，作者逐个定位、看顺序，再比年份、期刊、卷页、DOI，综合判断“是不是同一篇”。
6. `lib/verify/format.ts`：用数据库记录生成 GB/T 7714 / APA 写法，不补造任何数据库里没有的信息。
7. `components/result-card.tsx`：印章、一句话结论、字段比对、规范写法、核查过程；`report-summary.tsx` 做汇总、筛选和规范参考文献（`lib/report.ts`）。

### 9.4 其他几条调用链

- **AI 继续查**：`result-card.tsx` 点按钮 → `POST /api/agent` → `lib/agent/index.ts` 的 `runAgent`。循环为：调模型（`model.ts`）→ 解析工具调用（`tools.ts` 校验）→ 执行检索 → 规则比对，确认就停。最后用 `verifyReference` 带上额外候选重新判定。
- **论断核查**：`claim-checker.tsx` → `POST /api/claims` → `checkClaim`。依次是：取证据（`fulltext.ts` 全文，没有就用 `sources.ts` 摘要）→ 分块检索（`retrieval.ts`、`assist.ts`）→ `judgeRetrievedEvidence`（`model.ts`）→ `validateJudgment` 校验引句 → 矛盾时 `checkContradictionScope`。
- **截图识别**：`checker.tsx` 压缩图片 → `POST /api/vision` → `transcribeReferences`。识别结果显示给用户核对，确认后填入输入框。
- **导入**：`document-import.tsx` → `POST /api/import` → `importDocument`，PDF 走 `pdf.ts`（PDF.js worker + 隐藏文字钩子），DOCX 走 `docx.ts`，再经 `hidden.ts` 处理隐藏文字。

## 12. 术语表

| 术语 | 一句话解释 |
|---|---|
| DOI | 数字对象标识符，论文的“身份证号”，如 10.1038/nature14539；登记在 Crossref、DataCite、中国 DOI 等注册机构 |
| Crossref | 最大的学术 DOI 注册机构，提供免费查询接口，含 Retraction Watch 撤稿数据 |
| OpenAlex | 开放学术图谱，用来兜底检索英文题名、交叉核对撤稿 |
| DataCite | 软件、数据集、arXiv 预印本等的 DOI 注册机构 |
| 中国 DOI 注册机构 | 知网登记的中文 DOI 的落地页（chndoi.org），能读到登记的题名和作者 |
| Retraction Watch | 撤稿数据库，现在由 Crossref 开放提供 |
| GB/T 7714 | 国家标准的参考文献著录规则 |
| APA | 美国心理学会引用格式（第 7 版） |
| Function Calling | 让大模型按预先定义的函数格式输出参数，服务端校验后执行 |
| Agent | 模型多轮决定下一步调用哪个工具；本项目的 Agent 只能检索，不能下结论 |
| RAG | 检索增强生成：先检索证据片段，再让模型基于片段回答 |
| BM25 | 经典的关键词检索打分方法 |
| 倒数排名融合（RRF） | 把几种检索的排名合并成一个排名 |
| 重排 | 让模型给候选片段按相关性打分，取最相关的几段 |
| MRR | 平均倒数排名，出处片段排得越靠前越接近 1 |
| 多模态 | 模型处理图片等非文字输入；本项目指截图识别 |
| MCP | 模型上下文协议，让 AI 工具（Claude、Cursor 等）调用外部工具的标准 |
| stdio | 通过标准输入输出通信，本机进程之间用 |
| NDJSON / 流式 | 一行一个 JSON，服务端核完一条就推一条 |
| SSRF | 服务器端请求伪造：诱使服务器访问内网地址；本项目只请求公网地址 |
| EXIF | 照片里的元数据（位置、设备等），上传前去掉 |
| 盲测 | 规则定稿后在没见过的数据上只运行一次 |
| 误报 | 真实文献被标成有问题 |
| 相近候选 | 找到相近记录但不能确认是同一篇，单列，不算写错 |
