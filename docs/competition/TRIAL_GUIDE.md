# 老师试用指南

目的：请几位老师用真实的参考文献列表试用，记下“人工核对要多久、用工具要多久、工具标出的问题对不对”。这是比赛材料里“实用性”和“社会价值”最缺的证据。每位老师约 20–30 分钟。

## 一、试用前准备（我自己做）

**国内试用入口：[引用体检 · 魔搭](https://www.modelscope.cn/studios/kgkvybu111111/cite-checkup?mode=full)。** 老师直接用电脑或手机浏览器打开即可，不需要安装软件、连接同一 Wi-Fi 或保持我的电脑开机；已验证未登录魔搭也可使用。先点击“载入示例”→“开始体检”，再试自己的参考文献。

魔搭版已验证参考文献核查、真实 AI/论断/中文检索、图片转写、小 PDF/Word 导入及报告下载。应用标示上限为 8 MiB，但接近上限的云端上传请求本次超时，暂不能保证大文件导入；**试用先选小文件，大论文可直接复制参考文献文本**。这是部署验收，不是老师真实试用记录。

**备用入口：[Netlify 版](https://cite-checkup-ql514740.netlify.app)。**

线上 Netlify 版文件/图片合计上限为 **4 MiB**；单次核查超过 **50 秒**仍未结束，会保留已有结果并提示未完成，建议先用少量条目。2026-10-18 已验证线上 11 条示例、真实 AI 解析与论断核查、中文检索、图片识别、PDF/Word 导入及报告下载；这属于部署验收，不是老师真实试用记录。

下面是保留的**本机演示备用方式**，使用线上入口时不需要执行：

1. 在 `.env.local` 填好 `CROSSREF_MAILTO`（自己的联系邮箱）和 `OPENALEX_API_KEY`（openalex.org 免费申请）。没有 OpenAlex key 时，每天只有约 100 次题名检索，几位老师连着用可能会用完，之后“查无此文”会变成“检索不完整”。
2. 启动生产版（在项目目录的 Git Bash 里依次运行，代理端口按自己的实际情况改）：

   ```bash
   pnpm build
   ```

   ```bash
   NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1,::1 pnpm exec next start -p 3210 -H 0.0.0.0
   ```

3. 打开方式二选一：
   - 在我的电脑上用：浏览器打开 `http://localhost:3210`。
   - 老师用自己的电脑：两台电脑连同一个 Wi-Fi；我在命令行运行 `ipconfig` 查到本机 IPv4 地址，老师打开 `http://<这个地址>:3210`。第一次启动时，Windows 防火墙若询问是否允许 Node.js 访问网络，选“专用网络”允许。
4. 先自己跑一遍“载入示例”，确认 11 条都能出结论，再请老师试用。
5. 准备一张打印的记录表（见第四节），或者让老师直接填电子版。

## 二、怎么用（讲给老师听，3 分钟）

第一次打开会播约 2 秒的开场动画，右下角出现“带我看看”的邀请，可以跟着 6 步引导走一遍（页眉“怎么用”随时重看），也可以直接开始。

**参考文献体检（页面顶部左边的标签）**

1. 把参考文献列表粘进输入框：一条一行，或者带 [1]、1. 这样的序号。也可以点“导入文件”从 PDF / Word / TXT 里提取，或点“截图识别”上传参考文献页的照片。
2. 点“开始体检”，每条会陆续盖上一个章：
   - **已核实**：在数据库里找到同一篇，信息一致；
   - **有误**（信息有误）：找到同一篇，但作者、年份、期刊或 DOI 有写错的地方；
   - **相近候选**：只找到相似的文献，不能确定是不是同一篇，需要人工看；
   - **查无此文**（疑似不存在）：DOI 不存在或指向别的文献，或者英文期刊论文在两个数据库里都查不到，疑似编造；
   - **已撤稿 / 关注声明**：文献存在，但已撤稿或期刊发了关注声明；
   - **待人工**（无法核验）：图书、学位论文、网页、没有 DOI 的中文期刊等，开放数据库覆盖不到，查不到不代表有问题；
   - **未完成**：数据源暂时出错，可以稍后重试。
3. 结果上方可以按结论筛选，点“需要处理”只看有问题的条目。点卡片右下角的“详情”：能看到逐字段比对、按数据库记录生成的规范写法（可复制）和“核查过程”的每一步。
4. 对“待人工”或“相近候选”的条目，可以点“AI 继续查”：DeepSeek 会换着方式再查几个数据库，中文期刊论文还会联网搜索知网、万方、维普的论文页，每一步都显示出来，找到的候选仍由规则确认。知网、万方的搜索结果没有作者，这时只给“打开知网页面”之类的链接，请点开核对作者，工具不会直接判已核实。
5. 看完后可以“复制修正版清单”或“下载核查报告”。

**正文论断核查（页面顶部右边的标签）**

1. 输入论文正文里的一句话，例如“GPT-3.5 生成的参考文献有一半以上是编造的”。
2. 证据来源填这句话引用的文献的 DOI（开放获取论文效果最好），或者直接粘贴原文段落。
3. 结论分四类：证据支持、部分支持、矛盾、证据不足。下面列出判断所依据的原文句子，可以点开看在原文里的位置。

**要提前告诉老师的三点**

- “查不到”不等于编造，所有结论都要人工复核，工具只是帮忙把可疑的条目挑出来。
- 标准核验只把参考文献条目发给 Crossref、OpenAlex、doi.org 这类公开数据库。“AI 继续查”、截图识别、AI 辅助解析和论断核查会把相应文字发给 DeepSeek（“AI 继续查”查中文期刊时还会把题名发给 DeepSeek 的搜索接口）：未公开的学生论文先征得同意，敏感内容不要用这几项。
- 中文文献在标准核验里多数显示“待人工”，这是已知短板；中文期刊论文可以再点“AI 继续查”，约四成能找到知网、万方或维普的论文页，但多半要自己点开链接核对作者。

## 三、试用流程（每位老师）

1. 请老师带一份真实的参考文献列表（15–30 条，中英文都可以），最好是学生论文里还没人仔细核对过的。
2. **人工基线**：老师先用平时的方法核对其中 5 条，计时，记下发现的问题。
3. **用工具**：把整份列表粘进去体检，从粘贴到看完结果计时。
4. **逐条判断**：工具标出的“有误 / 相近候选 / 查无此文 / 已撤稿”，请老师逐条判断是“确实有问题 / 误报 / 拿不准”；再看人工发现、但工具没标出来的问题。
5. 任选一条“待人工”点“AI 继续查”（有中文期刊论文的，优先试一条中文），再试一次论断核查。
6. 填记录表；问一句：“如果指导学生写论文，你会不会让学生先用这个自查？为什么？”

## 四、记录表（每位老师一份）

完整的记录表是 [引用体检-老师试用记录表.xlsx](引用体检-老师试用记录表.xlsx)，直接发给老师填：基本信息、用时、逐条判断、漏报、卡点、理解检查、两组量表、开放问题、使用同意；黄色格子要填，多数格子下拉选择，逐条判断的合计和 SUS 得分自动计算，按 A4 分好了页，也能打印。表格由 [build_trial_form.py](build_trial_form.py) 生成。下面是其中的核心项。

| 项目 | 填写 |
|---|---|
| 编号与学科（不写真实姓名，如“T1 文学院”） | |
| 列表条数（中文 / 英文） | |
| 人工核对 5 条的用时（分钟） | |
| 工具检查整份列表的用时（分钟） | |
| 工具标出的问题条数 | |
| 其中：确实有问题 / 误报 / 拿不准 | |
| 人工发现、工具没标出的问题 | |
| 最有用的功能 | |
| 最困惑或最不满意的地方 | |

请老师按 1（完全不同意）到 5（完全同意）打分：

| 说法 | 1–5 |
|---|---|
| 不用别人教，我也能很快上手 | |
| 每条的结论和理由我看得懂 | |
| 我信任它标出的问题，愿意拿去提醒学生 | |
| 它能明显节省我核对参考文献的时间 | |
| 我会推荐学生在交论文前先用它自查 | |

**SUS 可用性量表**（System Usability Scale，Brooke 1996，https://doi.org/10.1201/9781498710411-35 ）：试用结束后马上填，同样 1（非常不同意）到 5（非常同意），不要回头改。

| 说法 | 1–5 |
|---|---|
| 1. 我想我会经常使用这个工具 | |
| 2. 我觉得这个工具没必要这么复杂 | |
| 3. 我觉得这个工具容易使用 | |
| 4. 我想我需要有人帮忙才能用好这个工具 | |
| 5. 我觉得这个工具的各项功能结合得很好 | |
| 6. 我觉得这个工具前后不够一致 | |
| 7. 我想大多数人都能很快学会使用这个工具 | |
| 8. 我觉得这个工具用起来很别扭 | |
| 9. 使用这个工具时我很有把握 | |
| 10. 我需要先学很多东西才能开始用这个工具 | |

计分：单数题得分减 1，双数题用 5 减得分，十题相加再乘 2.5，得到 0–100 分。分数高低可以对照 Bangor 等（2008，https://doi.org/10.1080/10447310802205776 ）汇总的大量 SUS 测试结果，但 5 个人左右的样本只能看出明显问题，不要把平均分当成定论。

另外请记下每个任务是否独立完成、卡在哪一步（自动化走查发现的疑点见 [USABILITY-2026-10-18.md](USABILITY-2026-10-18.md)，可以重点看老师会不会遇到）。

**理解检查参考答案**（记录表第六部分，只给组织者）：第 1 题选 B（疑似不存在，要人工确认），第 2 题选 C（开放数据库覆盖不到，要人工核对），第 3 题选 C（找到同一篇，信息一致），第 4 题选 A（只找到相似文献，要人工看）。选了“一定是编造”“这条文献有问题”“内容支持论文里的话”这类答案，说明界面让人理解错了，请记下是哪一题。

其他意见：

## 五、记录怎么用

- 记录表只写编号和学科，不写老师姓名；要在比赛材料里写“某某老师认为……”，先征得本人同意。
- 汇总后写进 README 和技术说明 PDF 的“试用反馈”：试用人数、平均用时对比、问题标注的准确情况、主要意见，以及据此做了哪些修改。只写实际发生的，样本少就如实写样本少。
