# 引用体检 · 论文参考文献核查

核查论文参考文献的**真实性、信息准确性与撤稿状态**，并比对**正文论断是否得到指定材料支持**。支持 PDF / DOCX / TXT 导入、拍照 / 截图识别、隐藏提示词检测、证据定位与报告下载。

> 在一项 2023 年研究的特定样本中，GPT-3.5 生成引文的 55% 为虚构，GPT-4 为 18%；这些比例不代表当前模型或所有使用场景。
> —— Walters, W. H., & Wilder, E. I. (2023). Fabrication and errors in the bibliographic citations generated by ChatGPT. *Scientific Reports*, 13, 14045. https://doi.org/10.1038/s41598-023-41032-5

**在线试用**：[引用体检 · 魔搭创空间](https://www.modelscope.cn/studios/kgkvybu111111/cite-checkup?mode=full)，不用登录，电脑、手机都能用。平台页面加载较慢，第一次打开要等约半分钟；上传文件请用几 MB 以内的，较大的论文可以直接复制参考文献文字。部署方式见 [docs/deployment/MODELSCOPE.md](docs/deployment/MODELSCOPE.md)。

**和直接问 AI 比**：同一批 130 条带真值的引文里，不联网直接问 DeepSeek 会把 23%–33% 的编造引文说成真实；本系统为 0，说“已核实”的全部正确，同一批重跑结论一致。联网的 AI 也很强，详见下文“和‘直接问 AI’的对照”。

| ✅ | 撤稿检查（Crossref 中的 Retraction Watch 数据 + OpenAlex 交叉核对） |

| ✅ | 停止核查、截断流检测、未完成报告标注；下载包含原文、问题、数据库记录与查询过程的报告（网页文件，可直接打开、打印或另存为 PDF；另有 Markdown 版） |

| ✅ | PDF 文字层 / DOCX / TXT 导入：提取预览、全文或参考文献区域选择、确认后替换输入 |

| ✅ | 拍照 / 截图识别：上传或直接粘贴参考文献页的截图、手机照片、扫描件截图，DeepSeek 视觉模型逐条转写，对照原图确认后再由规则核验 |
| ✅ | MCP Server：把“核验参考文献”“核查论断”开放给 Claude、Cursor 等 MCP 客户端（stdio） |
| ✅ | 隐藏提示词检测：导入时找出读者看不见、AI 却会读到的文字（白字、极小字号、不可见渲染、页面外、Word 隐藏格式、Unicode 隐形字符），标出像写给 AI 的指令，并从导入文字中去掉 |

## 核查流程

```
引文原文
  │  本地解析：切分条目、提取 DOI / arXiv / 年份 / 题名 / 期刊（不调外部服务）
  ▼
有 DOI？──是──► Crossref 按 DOI 取元数据 ──查不到──► doi.org 问注册状态 ──已注册──► 内容协商取元数据
  │                                                     └─未注册──► 记为"DOI 不存在"
  ▼（没对上同一篇）
Crossref 整条引文模糊检索 ──仍未找到且为英文──► OpenAlex 题名检索兜底
  ▼
对候选逐字段打分，选出最佳匹配 → 撤稿检查 → 给出结论 + 规范写法 + 核查过程
```

选择 **AI 辅助解析** 时，在查询数据库前增加 DeepSeek `verify_references` 工具调用。只有规则没解析出题名、类型又在开放数据库覆盖范围内（期刊、会议、预印本或认不出类型）的条目才发送；只写了一个名称的条目、图书和网页等不发送，规则已解析完整的条目也不发送。服务端固定条目边界，逐条验证原文与字段来源：某条返回的字段缺原文依据、序号重复或漏返回，只有这一条退回规则解析，不影响同批其他条目。模型只补充规则没提取到的字段，保留原文中的错误作者、年份和期刊等证据；摘出的刊名只校验、不用于比对。补上的字段在详情比对表里标“AI 摘出”，页面会提示发送了几条、补上几条、退回几条。模型无法直接给出真实性结论，也不能选择任意网络地址。

10-16 的旧版把全部条目整批交给模型、一条不合格就整批作废：dev 集上比标准规则少核实 1 条、多 1 条误报，3 批中 1 批整批退回。10-17 改为上面的做法，并用同一批数据库应答对照两种模式（规则组运行时录下应答，AI 组回放，只有 AI 补上题名后新发出的检索才联网；[对照记录](eval/results/ai-parsing-ab-2026-10-17.json)）：

| 集合 | 发送 / 补上 / 退回 | 与标准规则相比 |
|---|---|---|
| dev 108 | 6 / 2 / 0 | 结论逐条相同 |
| test 119 | 29 / 23 / 1 | 多核实 2 条（ECML/PKDD 2007 挑战赛、R 包 vegan），多抓出 1 条真错误（第一作者 Olson 被写成 “Carol”） |
| 第五批 108 | 8 / 8 / 0 | 结论逐条相同 |

改版过程中出过四处问题，都已修复并补了测试：
- 把“只有一个名称”的条目整句当题名（test T066）；
- 把章节题名当成书名补进刊名（T092）；
- 条目自带编号时，输入检查只去一次编号，整批被拒；
- 没有 DOI 的会议论文，题名由模型摘出后两个库都查不到，被判成疑似不存在（第五批 B052）。现在 AI 摘出的题名只用来找候选，查不到时不作为疑似不存在的依据。

结论：最终版本没有新增误报，收益很小，只出现在规则解析不出题名的会议论文和软件包上；test 集今天已用于改版，那 3 条不算独立证据。

**AI 检索 Agent（“AI 继续查”）**：标准核验后，“无法核验”或“只找到相近候选”的条目旁会出现“AI 继续查”按钮。点击后，DeepSeek 先阅读原文、已解析的字段和已经查过的路径，再决定下一步调用哪个工具：

- `search_crossref`：按题名或关键词检索，可加作者姓、年份 ±1；
- `search_openalex`：按题名检索，每条最多 1 次；
- `search_datacite`：检索软件、数据集、报告、学位论文和预印本；
- `lookup_doi`：只能查询引文或检索结果中出现过的 DOI；
- `search_cn_journals`：中文期刊论文按题名联网搜索知网、万方、维普的论文页（见下文“中文期刊联网检索”）；
- `finish`：结束检索。

每次调用都带一句中文理由，检索结果连同规则比对提示（题名、第一作者、年份是否吻合）回传给模型，供它调整下一步。每一步都实时显示在卡片上。规则一旦确认找到同一篇就停止；每条最多检索 4 次、调用模型 4 轮、耗时 80 秒。

结束后，所有候选交给与标准核验相同的规则逐字段比对：

- 模型不能指定哪一篇算数，不能给出真伪结论；
- Agent 只能找到证据，不能制造“疑似不存在”；
- 模型失败、超时或参数不合规时，原结论保持不变并如实说明。

**中文期刊联网检索**：知网、万方、维普没有开放接口，Crossref 和 OpenAlex 对中文期刊文章收录有限，10-17 重测时 AI 继续查对 53 条中文条目一条也没找到（见“AI 检索 Agent 评测”）。现在 Agent 多了 `search_cn_journals` 工具：用 DeepSeek 的 Search 接口（[`/v1/tools/search`](https://api-docs.deepseek.com/guides/search/)）按题名检索，限定 `site:cnki.net OR site:wanfangdata.com.cn OR site:cqvip.com`，只认这三站的期刊论文页，从搜索结果的标题、摘要和网址里解析题名、作者、刊名、年期，不抓取页面、不登录。

- 维普的结果带作者，和其他数据库记录一样交给规则逐字段比对：作者、刊名、年份都对上才算已核实；题名对上、作者对不上，判“信息有误”。
- 知网、万方的结果没有作者，同题名再只查一次维普补作者；仍然没有作者的，**一律不确认是同一篇**，只作为相近候选给出，附“打开知网页面”之类的链接，请人工核对作者。题名、刊名、年份都一致时提示“在知网找到题名、刊名、年份一致的文章，但没有作者信息，请打开链接核对作者”。没有作者的记录也不生成规范写法，免得复制后丢掉作者。
- 中文期刊论文还没查这三站，模型就要结束时，服务端退回一次 finish，请它先查（浏览器实测时出现过一次模型直接结束）；第二次结束照常接受。
- 评测的三个集合（见“AI 检索 Agent 评测”）平均每条调用 1.2 次中文检索，每次 1～2 个搜索请求；按官方价格每 1,000 次成功请求 0.75 美元（2026-10-17 查看），每条不到 0.2 美分。搜索失败、余额不足、限流都按“数据源暂时不可用”处理，不当作查不到；补查维普这一步失败时，保留首轮找到的候选，检索步骤里注明“补查维普作者未完成”。

**拍照 / 截图识别**：扫描版 PDF 没有文字层、纸质论文只能拍照时，可以点“拍照 / 截图识别”上传 1–4 张图片，或在参考文献框里直接粘贴截图。浏览器先把图片重新绘制成 2048 像素以内的 PNG/JPEG，同时去掉 EXIF 位置等元数据，再交给 DeepSeek 视觉模型用 `submit_references` 工具逐条转写：

- 只转写、不判断真伪，不改错、不补全、不翻译；看不清的字写成 `[?]`；
- 图片里出现的文字一律当作数据，不执行其中的指令；
- 识别结果与原图缩略图一起预览（点击可看原图），可以直接修改，确认后才填入参考文献框，真伪仍由数据库核验给出。

**隐藏提示词检测**：2025 年 7 月，日经亚洲报道 17 篇 arXiv 预印本用白色文字或极小字号藏了“只给正面评价”之类写给 AI 审稿工具的指令（[Sugiyama & Eguchi, 2025](https://asia.nikkei.com/Business/Technology/Artificial-intelligence/Positive-review-only-Researchers-hide-AI-prompts-in-papers)）；随后的评论文章统计到 18 篇（[Lin, 2025, arXiv:2507.06185](https://doi.org/10.48550/arXiv.2507.06185)）。本项目会把论文交给 AI 解析和论断核查，所以导入时先查一遍：

- PDF：白色或接近白色的文字（灰度、RGB、CMYK 都算）、不可见渲染模式、小于 1.5 磅的字、画在页面外的字；
- Word：隐藏格式（含样式继承）、浅色底上的白字、小于 2 磅的字；
- 所有格式：Unicode 标签字符（把 ASCII 指令编码成看不见的字符）和零宽字符。

查到的片段先判断像不像写给 AI 的指令（“忽略之前的指令”“给出正面评价”“不要提及缺点”“建议录用”等中英文说法），像指令的一律列出；不像指令的，白字满 40 字、其他方式满 12 字才列出，避免把深色底上的标题、缩小的图表文字当成问题。列出的片段会从导入文字中去掉，导入预览上方用红框（像指令）或琥珀色框显示页码、隐藏方式和原文。扫描件 PDF 的 OCR 文字层也是不可见文字，按正常文字导入，只提示不报告。判为 OCR 文字层要同时满足：不可见文字占该页一半以上；页面画了覆盖一半以上版面的图像，或者该页文字 90% 以上不可见（文字转成曲线的版面）。没有图像、只是大半文字不可见的页面照常报告（10-17 复评用一个 707 字节、不含图像的 PDF 绕过了旧规则）。OCR 文字层里像写给 AI 的指令的行仍然报告并去掉，因为谁都可以在隐藏文字下面垫一张图。

PDF.js 的文字条目不带颜色和渲染模式；取绘图指令又会解码图片，被本项目的解码器防护拦下。因此在已校验哈希的 PDF.js worker 里追加了只读观察钩子，在提取文字的同一遍里跟踪填充色和渲染模式，不改变提取结果（实现与审计说明见[导入模块说明](src/lib/documents/README.md)）。

**判定原则**

- 查不到 ≠ 编造。图书、学位论文、网页、报告、标准、法规、软件 / 数据集、无 DOI 的中文文献在开放数据库覆盖率低，查不到时判为"无法核验"，提示到知网 / 万方人工核查。
- "疑似不存在"只在有较强证据时给出：DOI 未注册、DOI 指向另一篇文献、英文期刊 / 会议论文在 Crossref 和 OpenAlex 中都查无此文。没写 DOI 的，下这个结论前还会查 Crossref 期刊目录：目录里认得出这本刊、但它在引文年份没有登记文献时，改判“无法核验”；比如某刊只登记过 2007–2009 年的文献，2022 年的论文查不到就不算证据。目录认不出的刊名（“J Surg Oncol”这类缩写，或根本不在 Crossref 的刊物）做不了这一步，所以真实刊物上的真实论文仍可能被判“疑似不存在”（第四批盲测的 B040），这类结论要人工复核。
- 判"期刊名不符"之前，先按 ISSN 查该刊在 OpenAlex 登记的其他名称（外文刊名、旧刊名），波兰语、缩写等写法不算错。
- 年份按正式出版、纸本、在线首发三个日期比对，写其中任何一个都不算错。物理、化学期刊常见的"不写题名"引文，按 DOI、作者、刊名、卷号、页码核对。
- 规范写法只依据数据库记录格式化生成，**不让大模型编写任何文献信息**。
- 网页搜索结果没有作者时不确认同一篇。知网、万方的搜索结果只有题名、刊名和年期，确认同一篇必须有作者可比，所以最多给“相近候选”和来源链接；只用题名确认，编造作者的引文就会被判成已核实。
- 相近候选不等于已确认同一篇。只找到相近记录、没能确认是同一篇的条目单独判为“相近候选”：哪一项写错要以确认同一篇为前提，所以它不算“信息有误”，需要人工核对；修正版清单保留原文并要求人工确认，不自动替换成另一篇文献。引用的 DOI 未注册或指向别的文献时，DOI 的错误是确定的，即使另有相近候选也仍判“信息有误”。
- 关注声明与撤稿分别显示。数据库故障、预算不足和核查中断不当作“查无此文”；未完成时不显示健康分，也不允许复制完整修正版。
- 撤稿状态除了读 Crossref，还按 DOI 到 OpenAlex 交叉核对。OpenAlex 有时把一个 DOI 并到登记了另一个 DOI 的记录里（示例中的 arXiv 论文《Attention Is All You Need》就是这样，2026-10-17 实测）：题名、第一作者都对得上，才用这条合并记录核对撤稿状态；对不上，或合并记录带撤稿标记，只提示人工核对，不据此判撤稿。
- 健康度仅计算有明确结论的条目，不包含相近候选、待人工核验及关注声明；匹配参考值不是经统计校准的正确概率。

## 快速开始

需要 Node.js 22.13+ 和 pnpm（PDF 解析依赖的最低版本）。

```bash
pnpm install
cp .env.example .env.local   # Windows PowerShell 使用 Copy-Item .env.example .env.local
pnpm dev                     # http://localhost:3210
```

已有 `.env.local` 时请直接编辑，不要覆盖。建议设置 `CROSSREF_MAILTO`；要启用 AI 模式，填入服务端 `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_MODEL`（默认 `deepseek-flash`）与 `DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）。修改配置后重启服务。没有密钥也可使用标准核验。

生产构建与启动：`pnpm build`，然后 `pnpm start --port 3210`。

项目自带 `.npmrc`，依赖从 npmmirror 国内镜像安装。

### 和“直接问 AI”的对照

评委和用户最常问：为什么不直接把参考文献丢给 ChatGPT、DeepSeek？我们构造了 130 条答案已知的引文（真实 50、改错一项 40、编造 40，含中文 20），同一批交给本系统和 DeepSeek（开深度思考、逐条单独问、允许答“不确定”，这些条件对 AI 有利）：

| 做法 | 编造被说成真实 | 改错被说成正确 | 改正写法改对 | 真实英文条目有结论 | 重问一遍结论相同 | 单条用时 |
|---|---|---|---|---|---|---|
| 本系统：规则核验 | 0/40 | 0/40 | 36/36 | 20/40 | 129/130 | 约 2 秒 |
| 本系统：规则 + AI 继续查 | 0/40 | 0/40 | 36/36 | 21/40 | — | 追查条目约 7 秒 |
| 直接问 AI（flash，不联网） | 13/40 | 7/40 | 15/37 | 37/40 | 115/130 | 7.5 秒 |
| 直接问 AI（pro，不联网） | 9/40 | 5/40 | 18/34 | 30/40 | — | 18 秒 |
| AI + 联网搜索（flash） | 0/40 | 0/40 | 39/39 | 40/40 | 108/130 | 8 秒 |
| AI + 联网搜索（pro） | 1/40 | 2/40 | 38/40 | 39/40 | — | 24 秒 |

- 不联网直接问 AI 不能用来核查：会一本正经地确认编造的文献，给出的 DOI 只有 56%–63% 指向正确论文。
- 联网的 AI 是真正的对手：flash 联网同样没有放过编造和改错，覆盖还更广；但 pro 联网把 2 条改过 DOI 的引文说成“与 PubMed 记录一致”，确认了 1 条虚构中文文献，两次运行有 17% 的结论不同。
- 本系统的长处是“说了就算数”：说“已核实”的 19 条全对，改正写法全部来自数据库，重跑结论一致，规则核验不调用模型。短处是网页、报告、图书多判“待人工”，也不检查格式是否完整（如 arXiv 编号多一位），这两点联网 AI 做得更好。

消融：去掉 OpenAlex 兜底，编造条目无法判为疑似不存在（10/30 降到 0）；加上 AI 继续查，中文真实条目 8/10 拿到“已核实”或“题名、刊名、年份一致”的链接，虚构的 0/10。数据集、提示词、逐条输出和局限见 [对照实验报告](docs/competition/COMPARISON-2026-10-18.md)。

- 题名边界：题名在 “, in:” 处截断；“E. coli” 这类物种缩写、学名后的命名人 “D. Don” 不当句号。
- 网页：判断期刊特征前去掉普通网址和访问日期（“Accessed on 31 August, 2023” 的 2023 不是卷号）；署名和末尾发布者同名的页面（“D&D Beyond. 2022. “…” D&D Beyond.”）按网页处理。这一条是为问号修复后变成“疑似不存在”的 B030 补的。

- 找到的多是知网、万方的页面，没有作者，所以确认的只有 1 条；把这些写成“已核实”需要作者信息，这一步只能请用户点开链接核对。用 Fetch 抓取知网、万方页面也拿不到作者（知网只有摘要和刊期，万方返回的是登录提示），还要多花 20 秒以上，所以没有用。
- 另取 12 条没找到的已看过期刊论文，换成加引号、加刊名、只限知网、不限站点四种写法再搜，只多找到 1 条（T098），说明主要卡在搜索引擎的收录，没有加这些回退。
- dev、test 两集已在开发中看过，第五批只运行了一次。数据集里的文献都真实存在，所以这里只说明“找得到”和“不误判成疑似不存在”，没有用编造的中文引文测过。按规则，编造的引文要么搜不到（保持“无法核验”），要么配到题名相近的真文章：维普记录的作者对不上判“信息有误”，知网、万方记录没有作者，最多给相近候选，都不会判已核实（有单元测试）。

盲测确认的 7 条逐条复核：

- **已核实的 4 条**：3 条正确；1 条匹配到同一作者 2026 年的同名新文章，不是被引的 2008 年章节。
- **信息有误的 3 条**：1 条引文确实把作者名写错了；1 条是匹配到 CRS 报告的旧版本，属于误报；1 条无法确认。

盲测之后补了两条保守规则：

- 报告、图书等覆盖不足的类型，AI 找到的记录与引文有出入时，只作为候选给出，不判“信息有误”；
- 图书、学位论文年份差距大时，题名必须几乎逐字一致才算同一篇。

修正后，上面两条误判都不会再出现，但 test 集已经用过，没有重测。dev 集第一次运行发现的两处规则误判也已修正，记录保留在 [agent-dev-2026-10-15-first.json](eval/results/agent-dev-2026-10-15-first.json)。

## MCP Server

`pnpm mcp` 以 stdio 方式启动 MCP Server（官方 TypeScript SDK 1.31.0），提供两个只读工具：

| 工具 | 输入 | 输出 |
|---|---|---|
| `verify_references` | `references`：参考文献列表（最多 80 条 / 60,000 字符） | 每条的结论、问题、数据库匹配记录和规范写法；逐条发送进度通知 |
| `check_claim` | `claim` 加 `doi` 或 `evidence_text`（二选一） | 支持 / 部分支持 / 矛盾 / 证据不足，附逐字核对过的原文引句 |

两个工具都同时返回文字摘要和带输出结构定义（outputSchema）的结构化结果。结论分别来自数据库逐字段比对和原文引句校验，与网页端相同；`verify_references` 的结论从服务端 0.2.0 起多了 `near_match`（相近候选：只找到相近记录、未确认是同一篇，不算信息有误）；`check_claim` 需要 `.env.local` 里的 DeepSeek 密钥，没有密钥时返回明确的“未配置”错误。

Claude Desktop（`claude_desktop_config.json`）或 Cursor（`.cursor/mcp.json`）中添加：

```json
{
  "mcpServers": {
    "cite-checkup": {
      "command": "pnpm",
      "args": ["--silent", "--dir", "D:/Darks/projects/cite-checkup", "mcp"],
      "env": { "NODE_USE_ENV_PROXY": "1" }
    }
  }
}
```

- 把路径换成你的项目目录；
- `--silent` 不能省，否则 pnpm 的提示会混进 stdout 的协议消息；
- 不走代理时可以去掉 `env`；
- 服务端按脚本位置读取 `.env.local`，与客户端的工作目录无关。

`pnpm smoke:mcp` 用同样的命令启动服务端，列出工具，并真实调用两个工具（[记录](eval/results/mcp-smoke-2026-10-16T00-35-59-125Z.json)）：两条公开文献一条已核实、一条查出年份写错；DOI 摘要论断判为“证据支持”，并附原文引句。

## 技术架构

- **前端**：Next.js 16（App Router）+ React 19 + TypeScript（strict）+ Tailwind CSS 4
- **接口**：`GET /api/check` 返回 AI 配置可用状态；`POST /api/check` 接收 `{text, mode: "standard" | "ai"}`，NDJSON 流式返回阶段、降级提示、结果及完成统计
- **导入**：`POST /api/import` 接收 `FormData.file`，返回纯文字、参考文献区域、格式/页数/警告，以及隐藏文字检测结果 `hidden`（没有时为 `null`）。确认预览后才替换用户输入；不调用 AI、不持久保存原文件。支持 8 MiB、100 页以内的文字 PDF、DOCX、TXT，不支持旧版 DOC 和加密文件；扫描版 PDF 没有文字层，会提示截图后走图片识别。
- **图片识别**：`GET /api/vision` 返回可用状态；`POST /api/vision` 接收 `FormData.image`（1–4 张，合计 8 MiB 以内），按文件头识别 PNG / JPEG / WebP / GIF，返回 `{entries, text, warnings, model, images}`。只转写不核验，实现见 `src/lib/vision/`。
- **AI 检索**：`GET /api/agent` 返回可用状态；`POST /api/agent` 接收 `{raw, index}`（单条引文，最多 2,000 字符），以 NDJSON 逐步返回 `step`，最后返回规则复核后的 `result`（含 `agent` 追查记录：工具调用次数、模型轮数、token、追查前结论）。实现见 `src/lib/agent/`。
- **论断 RAG**：`GET /api/claims` 返回配置与限制；`POST /api/claims` 接收 `{claim, doi}` 或 `{claim, evidenceText, evidenceLabel?}`。
  - DOI 证据依次尝试：Europe PMC 开放全文（JATS XML，去掉参考文献、表格和公式）、arXiv 预印本 PDF（DOI 本身是 arXiv，或出版社在 Crossref 登记了预印本），PDF 走与导入相同的安全解析器和隐藏文字检测；都没有时用 Crossref / OpenAlex 摘要。
  - 固定分块后，长材料（多于 6 段）用混合检索：原论断的 BM25 与模型扩展检索词（`expand_query`，中英文同义词、缩写）的 BM25 按倒数排名融合取 20 段，再由模型按 0–3 分重排（`rank_evidence`），取前 6 段；任一步失败都退回词面检索并在结果里说明。
  - DeepSeek `judge_claim` 输出支持、部分支持、矛盾或不足；服务端校验来源 ID、片段 ID、原文引句及位置。DeepSeek 没有向量接口，所以没有用向量检索。实现见 `src/lib/claims/`（`fulltext.ts`、`assist.ts`、`retrieval.ts`）。
- **数据源**：Crossref REST API、doi.org（注册查询 + 内容协商）、OpenAlex API、DataCite API；AI 检索的中文期刊检索用 DeepSeek Search API，只认知网、万方、维普的期刊论文页
- **字体**：思源宋体、霞鹜文楷、IBM Plex Mono，均自托管并按字符分片加载（不依赖 Google Fonts）

```
src/
├─ app/
│  ├─ page.tsx               首页
│  └─ api/check/route.ts     流式核查接口
├─ components/               送检单、结论卡片、体检报告、印章
└─ lib/verify/               核验引擎（与 UI 无关，可单独测试）
   ├─ extract.ts             本地解析
   ├─ normalize.ts           中英文归一化与相似度
   ├─ match.ts               逐字段比对与同一篇判定
   ├─ verify.ts              核查流程编排与结论
   ├─ format.ts              GB/T 7714 / APA 格式化
   ├─ http.ts                限流、重试、缓存
   └─ sources/               crossref / doi / openalex / datacite 适配，cnweb 为中文期刊联网检索
```

`src/lib/ai/` 负责模型请求与工具参数校验；`check-request.ts`、`check-limits.ts` 负责输入和调用额度；`check-stream.ts` 验证前端收到的完整结果流；`report.ts` 生成可复核的报告。

## 隐私与安全

- 参考文献标准模式把条目发送给公开学术数据库；选择 AI 解析后，还会把条目发送给 DeepSeek。论断核查把论断、最多 20 段候选片段（重排）和最终 6 段（判断）发送给 DeepSeek；请仅提供有权处理的内容，不上传个人隐私。
- 开放全文只访问 www.ebi.ac.uk 和 export.arxiv.org 两个固定主机，不跟随跳转；XML 最多 6 MiB，PDF 最多 8 MiB，正文最多 150,000 字符。查询扩展和重排的输出逐项校验（检索词不能含网址，重排只能用候选片段的编号），它们只决定交给判断的片段，不产生结论。
- API Key 只放在 `.env.local`，仓库中只提交 `.env.example`。
- 核查接口每 IP 每分钟最多 6 次、每次最多 80 条 / 60,000 字符。AI 每 IP 每分钟 2 次、每进程每小时 30 次、同时 2 次、单次 20,000 字符；超过 AI 限额时明确回退标准核验。
- 限额在当前 Node 进程内计数，重启会清空，多实例不会共享。访客按 `x-forwarded-for` 的第一段区分；魔搭演示是单实例，平台是否转发访客真实地址没有验证，多人同时使用时可能共用额度。正式服务需要可信代理覆盖该请求头，并增加共享限流和账户预算；目前不是生产级账户计费系统。
- AI 检索每 IP 每分钟 6 次、每进程每小时 60 次、同时 2 次；单条最多 4 次检索、4 轮模型调用、80 秒。工具参数逐项校验（工具名白名单、字段白名单、长度、年份范围、DOI 格式），DOI 只能查引文或检索结果中出现过的；检索只访问固定的学术数据源，中文期刊检索只把题名发给 DeepSeek Search，站点限定由服务端写死，模型不能指定网址；模型写的理由和小结会去掉网址，只作为过程说明显示。
- 图片识别把图片发给 DeepSeek，原图只在请求内存中使用、不保存；上传前在浏览器重新编码，去掉 EXIF 等元数据。每 IP 每分钟 4 次、每进程每小时 40 次、同时 2 个；单次最多 4 张图、80 条、60,000 字符，60 秒超时。只接受文件头真实为图片的文件，模型只能调用 `submit_references`，返回的字段、条数和长度逐项校验。
- 引文工具只允许 `verify_references`；论断工具只允许 `judge_claim`。未知工具、非法字段、虚构引句、错误来源编号、截断或超大响应均被拒绝；材料中的指令视为待分析数据。取消会停止模型请求及后续查询。
- 论断核查单次论断最多 2,000 字符、证据 160,000 字符；每 IP 每分钟 6 次、每进程同时 2 次、每小时 30 次及输入 240,000 字符。模型和来源失败标为未完成，不伪造判断。导入解析资源与 ZIP/XML 边界详见 [导入模块说明](src/lib/documents/README.md)。
- 已知瞬时连接错误最多重试一次，共用 60 秒总超时；鉴权、HTTP 错误及内容校验失败不重试。生产日志只输出固定错误分类，不记录引文、密钥、地址或原始异常。

## 已知局限

- 中文文献：知网、万方没有开放接口。标准核验只能核验已在 Crossref 注册 DOI 的中文文献；AI 继续查能在知网、万方、维普找到约三分之一到一半的中文期刊论文页（上面三个集合 33 / 75），但知网、万方的结果没有作者，多数只能给出带链接的相近候选，由用户核对作者。学位论文、图书、报纸仍需人工核查。
- 作者已支持汉字与拼音互相比对；中文题名对应英文元数据（或反过来）时仍无法比对题名。
- 会议论文的期刊名差异较大，目前只对期刊类文献做期刊名比对。
- 论断判断只针对指定来源及召回文字；只有 Europe PMC 开放获取子集和 arXiv 能读到全文，其余 DOI 仍只有摘要；预印本可能与正式版本不同。用户提供的材料真实性未经独立认证，不做跨文献系统综述。原文引句存在也不保证模型解释正确，仍需人工复核；该流程不额外查询撤稿状态。
- AI 检索 Agent 只能查 Crossref、OpenAlex、DataCite、doi.org 覆盖的文献，以及 DeepSeek 搜索引擎收录的知网、万方、维普论文页；图书馆目录仍需人工核查；OpenAlex 无密钥时每天约 100 次题名检索。
- MCP Server 目前只提供 stdio 本地进程，没有远程 HTTP 部署与鉴权；论断核查与网页端共用每进程每小时 30 次的限额。
- 图片识别只转写参考文献条目，不理解图表；评测只覆盖清晰的印刷体，手写、强反光或严重透视的照片可能漏字，需要对照原图修改。iPhone 的 HEIC 照片需先截图或转成 JPG。
- 隐藏文字检测不覆盖：被图片或色块盖住的字、透明度为 0 的字、裁剪掉的字、批注和表单里的字。PDF 没有“背景色”的概念，深色色块上的白字只能靠长度和内容区分；是否有意为之仍需人工判断。
- 规则只认学术数据库的记录：网页、报告、图书多数判“待人工”，也不检查格式是否完整（如作者列表不全、arXiv 编号多一位）。对照实验里联网 AI 在这两点做得更好，下一步是网页类引文打开网址核对标题，并让 AI 只给格式建议、不下真伪结论。
- 没有账户系统或共享限流。魔搭上的公开演示使用平台免费资源、单实例，适合试用和评审，不是正式服务：第一次打开要等约半分钟，所有访客共用 AI 调用额度，接近 8 MiB 的上传在平台上没有验证通过。
